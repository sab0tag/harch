# 07. ИИ в системе

## Принцип

**ИИ готовит черновик, человек решает.** Любой результат модели попадает в систему только как
черновик у maker'а с пометкой «Запропоновано ШІ». Сохранить, подать или утвердить может только
человек. Автоматических approve нет и не будет.

## Где ИИ нельзя использовать

- Расчёт розходу, БЖУ, ккал, списання — только детерминированный код (`consumption/calc.py`).
- Любые переходы задач в workflow.
- Данные пациентов (их в системе нет и не будет).
- Система обязана полностью работать без ИИ: нет ключа, API недоступен, фича выключена → все
  экраны работают, просто не показываются кнопки ИИ.

## Ключ и настройки

```
AI_ENABLED=false                  # глобальный выключатель
ANTHROPIC_API_KEY=                # только в .env на сервере; никогда в git, в чатах, в логах
ANTHROPIC_MODEL=claude-sonnet-5   # модель задаётся конфигом, не хардкодом
AI_DAILY_REQUEST_LIMIT=200        # защита от случайного перерасхода
```

- Отдельный ключ под этот проект; в консоли Anthropic выставить месячный лимит расходов.
- Ключ читается один раз в `apps/assist/client.py`; нигде больше не упоминается.
- В тестах реальный API не вызывается никогда — клиент подменяется фейком.

## Модуль `apps/assist`

```python
class AIRequestLog(Model):            # журнал каждого вызова
    user = ForeignKey(User)
    feature = CharField()             # "card_import", ...
    model = CharField()
    status = CharField(choices=[ok, error, rejected_by_limit])
    input_tokens, output_tokens = PositiveIntegerField(null=True)
    duration_ms = PositiveIntegerField(null=True)
    request_meta = JSONField()        # размер файла, число страниц — НЕ содержимое
    response_json = JSONField(null=True)
    error = TextField(blank=True)
    created_at = DateTimeField(auto_now_add=True)
```

`client.py` — единственная точка вызова модели:
`extract(feature, system_prompt, content_blocks, tool_schema) -> dict`. Структурированный ответ
получаем через принудительный вызов инструмента (tool use) с JSON-схемой, а не парсингом текста.
Проверка лимита, запись в журнал, таймаут и один ретрай — внутри клиента.

## Фича 1 (Sprint 1A): оцифровка карток-розкладок

**Сценарий.** Дієтсестра фотографирует бумажную картку-розкладку или страницу сборника →
загружает на экран «Імпорт картки» → через 10–20 секунд видит слева фото, справа
заполненную форму картки → правит → «Створити картку». Картка создаётся с `verified=False`,
`origin="ai_import"` и ссылкой на черновик.

**Что извлекает модель (схема инструмента):**
```json
{
  "dish_name": "string",
  "card_no_on_paper": "string|null",
  "output_g": "number|null",
  "category_guess": "string|null",
  "ingredients": [
    {"product_raw": "string", "brutto_g": "number|null", "netto_g": "number|null",
     "confidence": "high|medium|low"}
  ],
  "technology": "string|null",
  "source": "string|null",
  "warnings": ["string"]
}
```
Правило в промпте: если число не читается — `null` и предупреждение, **никогда не угадывать**.

**После модели — детерминированная обработка:**
1. Сопоставление `product_raw` со справочником продуктов: точное совпадение → нечёткое
   (нормализация регистра/пробелов/«ё-е», difflib ≥ 0.85) → иначе «Новий продукт?» (создаёт
   только человек, с вводом БЖУ).
2. Проверки: нетто ≤ брутто; нет пустых чисел; сумма нетто правдоподобна относительно выхода;
   дубль названия с существующей карткой.
3. Всё проблемное подсвечивается на форме жёлтым/красным; кнопка «Створити» активна только
   когда нет красных ошибок.

**Модели:**
```python
class DishImportDraft(Model):
    uploaded_by = ForeignKey(User)
    image = ImageField()              # хранится в media/, ужимается до 2000px по длинной стороне
    status = CharField(choices=[processing, ready, failed, accepted, discarded])
    extracted = JSONField(null=True)  # сырой ответ модели
    ai_log = ForeignKey(AIRequestLog, null=True)
    dish = ForeignKey(Dish, null=True)  # созданная картка после accept
```

**Доступ:** admin, dietician.

## Оценка качества до включения пользователям (AI-04)

Это обязательный шаг, а не «потом».
- Набор 15–20 реальных фото карток из больницы + вручную набранный эталон (`evals/cards/*.json`).
- `python manage.py eval_card_import evals/cards/` → отчёт: доля верно извлечённых названий
  продуктов, точность чисел брутто/нетто (точное совпадение), доля полей, где модель честно
  вернула `null` вместо ошибки.
- Порог включения: ≥ 95% чисел точно, 0 «уверенных» ошибок (confidence=high, но число неверно).
- Прогонять при смене модели или промпта. Результаты хранить в `evals/reports/`.
