# 01. Домен и процесс

## Как сейчас (на бумаге)

1. Старшие медсёстры отделений пишут на листке, сколько пациентов и на каких дієтах — несут на пищеблок.
2. Дієтсестра сводит листы, составляет меню-розкладку на день, считает продукты по карткам-розкладкам.
3. Меню-розкладку утверждает директор (по реестрам и сайту больницы руководитель — «Директор»; медичний директор — отдельная должность), подписывают дієтолог, бухгалтер, шеф-кухар.
4. Кухня получает продукты со склада и готовит по карткам-розкладкам.
5. Бухгалтерия списывает продукты и ведёт накопичувальну відомість за месяц.

Боль: ручное сведение и переписывание одних и тех же цифр 3–4 раза в день, ошибки
арифметики, потерянные листы, неделя подготовки к проверкам.

## Как будет (в системе)

```
[dept_nurse]  Замовлення відділення на дату D (порції по дієтах)
      │ submit
      ▼
[dietician]   Перевіряє замовлення → approve / reject(коментар)
      │ все замовлення approved (или дедлайн)
      ▼
[dietician]   План меню на D: одне меню на кожну дієту → submit
      │
      ▼
[chef]        Перевіряє план (чи є продукти, чи реально приготувати) → approve / reject
      │ approve → система фиксирует снапшот розходу
      ▼
[chef]        Приготування: відмічає виконання, вносить відхилення факт vs план → submit
      │
      ▼
[dietician]   Бракераж / підтвердження → approve
      │
      ▼
[accountant]  Списання продуктів за D за снапшотом (+ відхилення) → submit
      │
      ▼
[dietician]   Звірка → approve. День закрито.
```

Каждая стрелка — задача (Task) в движке maker/checker. См. `03_task_engine.md`.

## Термины (Наказ №931)

| Термин | Что это в системе |
|---|---|
| Варіант дієти (ОВД, ЩД, ВБД, НБД, НКД) | `Diet(kind="variant")`. Заменили столы Певзнера в 2013 |
| Спеціальна дієта (№1а, №4, №9) | `Diet(kind="special")`. Назначается дополнительно; в пилоте №9 имеет собственные меню |
| Картка-розкладка | `Dish` + `DishIngredient`. Постоянная рецептура на 1 порцию: брутто, нетто, вихід |
| Меню-розкладка | Документ дня: `DailyPlan` + снапшот розходу. Утверждается и подписывается |
| Порційна вимога / замовлення | `DailyOrder` + `DailyOrderLine` |
| Брутто / нетто | Масса до / после холодной обработки. Закупка по брутто, калорийность по нетто |
| Вихід | Масса готовой порции |
| Накопичувальна відомість | Месячная сводка списания продуктов по дням (отчёт) |
| Бракераж | Органолептическая оценка готовой еды перед раздачей (v0.2 — журнал) |

## Прийоми їжі

`breakfast` Сніданок · `second_breakfast` 2-й сніданок · `lunch` Обід ·
`afternoon_snack` Полуденок · `dinner` Вечеря.
Набор приёмов настраивается у дієти (не все дієти имеют полуденок) — пока все пять.

(предупреждение, не блокировка — решение за дієтологом).

## Открытые вопросы к пищеблоку (уточнить до Sprint 3)

1. До какого часа отделения подают замовлення на завтра? (по умолчанию 16:00 D-1)
2. Кто реально утверждает план меню — шеф-кухар, дієтолог или головний лікар? Кто checker?
3. Отделение заказывает одной дієтой или разбивкой по нескольким дієтам?
4. Как оформляется дозамовлення (поступил пациент после подачи)? Отдельная корректировка на обед/ужин?
5. Сколько приёмов пищи фактически — 4 или 5? Одинаково ли для всех дієт?
6. Картки-розкладки у больницы свои (утверждённые) или используются типовые из сборника?
7. Нужна ли печатная форма меню-розкладки 1:1 с текущим бумажным бланком? (сфотографировать бланк)
8. Кто в бухгалтерии принимает списание и в какой системе они ведут учёт (1С/BAS/Excel)? Нужен ли экспорт в конкретном формате?
