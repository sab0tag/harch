# 05. План спринтов v0.1

Темп: ~8–10 ч/неделю. Спринт ≈ 1 неделя. Каждый тикет = отдельный коммит с ID.
Тикет готов, когда выполнены все критерии приёмки и зелёные тесты.

## Sprint 0 — Каркас

**S0-01 Проект и окружение.** Django 5 + Postgres в docker compose, settings base/dev/prod через django-environ, `.env.example`, pytest настроен, `uk`/`Europe/Kyiv`.
- ✅ `docker compose up` поднимает web+db, `pytest` проходит пустой тест, `/admin/` открывается.

**S0-02 Пользователь и роли.** Кастомный `User` с `role` и `department` (миграция до первого `migrate`!), `RoleRequiredMixin`, декоратор для function views.
- ✅ constraint: dept_nurse без відділення не сохраняется; тест прав на 403.

**S0-03 Layout.** `base.html`: сайдбар по ролям (из одного конфига `NAV_ITEMS` с полем `roles`), шапка, offcanvas на мобильном, логин/логаут на українській.
- ✅ под каждой из 5 ролей видны только свои пункты (тест рендера меню).

## Sprint 1 — Справочники и seed

**S1-01 Модели catalog/orgstructure/menus** по `02_data_model.md`, simple-history, admin-регистрация.
  `Department` уже создан в S0-02 (нужен для FK пользователя) — здесь добавить `default_diet` (FK на `Diet`).
**S1-02 `load_seed`** — management command, идемпотентная (повторный запуск не дублирует), грузит `seed/*.json` в порядке diets → products → departments → dishes → menus → substitutions/seasonal. Все записи `verified=False`.
- ✅ после загрузки: 8 дієт, 72 продукти, 15 відділень, 130 карток, 250 меню; каждое меню проходит валидацию «страва допустима для дієти меню» (если нет — лог предупреждения, не падение).

**S1-03 Экраны довідників**: список карток с фильтром по категории/дієте/«не перевірено», картка с пересчётом БЖУ, редактирование інгредієнтів (HTMX-строки).
**S1-04 Экран меню**: список 250 с дієтою и ккал vs норма (цвет), детальная страница по прийомам їжі.
**S1-05 `calc.py` + unit-тесты** на контрольный пример из `02_data_model.md`.
- ✅ тест с меню №1×10 + №81×5 даёт ровно цифры из таблицы.

**AI-02 Импорт картки по фото**: загрузка (jpg/png/pdf ≤ 10 МБ, ужатие до 2000px),

**AI-04 Оценка качества**: `evals/cards/` (15–20 реальных фото + эталон), команда

- ⚠ Блокер: нужны фото реальных карток из больницы (попросить у дієтсестри).

**AI-05 Журнал ИИ для admin**: список вызовов, токены, ошибки, использование за день/месяц.

## Sprint 5 — Прод и пилот

**S5-01 Prod-compose**: gunicorn, Caddy с доменом, WhiteNoise, `DEBUG=False`, security settings (`SECURE_*`, HSTS), `check --deploy` без предупреждений.
**S5-02 Бэкапы**: ежедневный `pg_dump` + ротация 14 дней + выгрузка в Hetzner Storage Box/B2; проверенная процедура восстановления в `docs/06_deploy.md`.
**S5-03 Пользователи пилота**: команда `create_pilot_users` из CSV (ПІБ, роль, відділення, телефон), генерация временных паролей, смена при первом входе.
**S5-04 Инструкции**: 1 страница на роль (PDF) — «що я роблю щодня в системі».
**S5-05 Мониторинг**: healthcheck endpoint, uptime-проверка (UptimeRobot/Better Stack), Sentry (бесплатный план).
**S5-06 Операційний аудит** (делать в первую неделю пилота, когда есть реальные данные для порогов):
команда `operational_audit --days N` по крону (по умолчанию раз в 7 дней) — **детерминированные
проверки кодом, без ИИ**: факт vs план > X% без причины (`ActualConsumption`); списання больше плана
или цена 0 (`WriteOffLine`); відділення систематически подают замовлення после дедлайна; частые
reject'ы по типу задачи/этапу; задачи в `submitted` дольше суток; скачки порций відділення
относительно его медианы; утверждённый план без факта/списання; меню в плане ниже нормы ккал дієти.
Есть находки → код создаёт задачу `operational_review` (maker — dietician, checker — admin) со
списком; каждая находка закрывается комментарием или отметкой «норма». Пороги — в settings.
ИИ (опционально, позже) — только текстовое резюме отчёта; находки и задачи от него не зависят.
- ✅ unit-тест на каждую проверку; без находок задача не создаётся; повторный запуск за тот же период не дублирует задачу.

- ✅ пищеблок работает 2 недели параллельно с бумагой; сравнение цифр розходу система vs бумага.

**S5-07 Імпорт цін з Excel** (бухгалтерия ведёт учёт в Excel, 1С нет): бухгалтер (и дієтсестра) загружает
свой `.xlsx` — прайс, накладную, оборотку. Столбцы «назва / ціна / од. вим.» находятся по заголовкам или
выбираются вручную и запоминаются. Строки сопоставляются с продуктами: запомненная привязка → точное
имя → похожее (редкие слова весят больше частых, разные числа не совпадают) — похожие только
предлагаются. Предпросмотр «було → стане», изменения > 30% подсвечены; применяются только отмеченные
строки, одной транзакцией, с историей «Імпорт цін: <файл>». Ручная привязка запоминается (`ProductAlias`).
`.xls` не читается — просим пересохранить в `.xlsx`. Без ИИ.
- ✅ поданные и затверджені списання не меняются (цены в них зафиксированы при подаче); тесты на
  разбор цен, единицы (г, 100 г, л, шт), сопоставление, повторный файл, права.
