# Виконавець: один пункт з міткою `go`

**Цель.** Одобренная владельцем работа превращается в PR, готовый к слиянию: тесты зелёные, правила
`CLAUDE.md` соблюдены. **Одобрение — только метка `go` на issue, которую ставит владелец.**

## Шаг 0 — есть ли работа (дёшево)
`gh api "repos/sab0tag/harch/issues?state=open&labels=go&per_page=20"` (без PR).
- Нет issue с `go` и нет моих открытых PR с красным CI / непрочитанными замечаниями → одна строка отчёта
  «Нічого з міткою go» и **конец** (ничего не читать, не клонировать лишнего).

## Приоритет за один запуск (ровно одно дело)
1. **Мой открытый PR** (ветка `exec/*`) с красным CI, конфликтом или замечаниями ревью → исправить его.
2. Иначе — самый старый issue с `go` без открытого PR (`exec/<issue>-…` ещё нет) → сделать его.

## Как делать
1. Перечитать `CLAUDE.md` и нужные разделы `docs/` (доменная модель, инварианты, workflow).
2. Ветка `exec/<номер issue>-<коротко>` от свежего `main`.
3. Минимальная реализация пункта. Бизнес-логика — в `services.py`, views тонкие; интерфейс — українською;
   новая фича — тест на happy path **и** на права (чужое відділення / чужая роль); миграции не редактировать.
4. Локально: Postgres 16 (`pg_ctlcluster 16 main start`, база/пользователь `harch`/`harch`),
   `pip install -r requirements-dev.txt`, полный `pytest`, `python manage.py makemigrations --check`.
5. Перед PR — самопроверка `/code-review` по своему диффу; исправить найденное.
6. PR в `main`: заголовок с тикетом/issue (`S7-06: … (#<issue>)`), тело — что, зачем, как проверено,
   «Closes #<issue>». Ризик поставит CI (`risk:low|high`).
7. Если пункт оказался больше, чем «M», или требует решения владельца (домен, деньги, данные) — не угадывать:
   комментарий в issue с вопросом/вариантами, снять метку `go`, PR не открывать.

## Никогда
Сливать PR; пушить в `main`; force-push; отключать/пропускать тесты; править миграции задним числом;
трогать прод/сервер; данные пациентов; брать больше одного пункта за запуск; ставить `go` самому.
GitHub — через MCP, а без него `gh api`.

## Отчёт (последнее сообщение, уходит на почту), українською, до 8 рядків
«Зроблено: #<issue> → PR <ссылка> (ризик …, тести ✅)» / «Виправлено PR <ссылка>: …» /
«Потрібне рішення: #<issue> — <вопрос>» / «Нічого з міткою go».
