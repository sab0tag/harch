# Залежності та безпека

**Цель.** Ни одна зависимость из `requirements.txt` / `requirements-dev.txt` не имеет известной уязвимости
в версиях, которые ставит текущий диапазон.

**Как.**
1. Чистое окружение: `python3.12 -m venv /tmp/deps && /tmp/deps/bin/pip install -q -r requirements-dev.txt pip-audit`.
2. `/tmp/deps/bin/pip-audit -r requirements.txt -r requirements-dev.txt --desc` (если сеть не пускает к базе
   уязвимостей — так и написать в отчёте, не придумывать результат).
3. `/tmp/deps/bin/pip list --outdated` — только для отчёта: что вышло за верхней границей диапазона.

**Готово, когда** одно из двух:
- уязвимостей нет → ничего не менять, только отчёт;
- есть уязвимость, которую текущий диапазон не исключает → ветка `deps/<дата>`, минимальная правка диапазона
  (поднять нижнюю границу до исправленной версии), полный `pytest` и `python manage.py makemigrations --check`
  зелёные локально (Postgres 16: `pg_ctlcluster 16 main start`, база/пользователь `harch`/`harch`), PR в `main`
  с описанием: пакет, CVE/GHSA, было → стало, результаты тестов. Коммит: `deps: …`.

**Никогда:** мажорные обновления; правки кода, кроме минимально нужных для совместимости; слияние PR;
пуш в `main`; добавление lock-файла без запроса.

**Бюджет:** один PR за запуск. Если для исправления нужен мажор или правка кода — не делать, описать в отчёте.

**Отчёт (последнее сообщение, уходит на почту), українською, до 10 рядків:**
`Залежності: ✅ вразливостей немає` или `⚠️ <пакет> <CVE> → PR <ссылка>`; затем «Нові мажорні версії: …» (или «—»).
